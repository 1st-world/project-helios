# 재사용 가능한 실제 Provider 통신 기록

이 폴더는 Helios가 실제 Provider와 통신한 요청·응답·공개 요약·도구 결과·사용량을 재사용하기 위한 공유 자료입니다. 검증 계획, 프런트 검사, 화면 캡처, 로컬 회귀 검사 및 실행 도구는 포함하지 않습니다. 입력은 작은 합성 파일과 질문이며, 실제 사용자 프로젝트를 공개한 자료가 아닙니다.

[기록 목록](results.json)에서 새 통신과 이전 관찰을 구분합니다. 같은 호출을 다른 관찰의 근거로 참조해도 호출 수와 비용에는 한 번만 반영합니다.

`runs/`에는 날짜별 실제 실행 기록과 집계를, `history/`에는 레거시 통신 묶음과 기존 대화의 저장 관찰을 둡니다. 레거시 `api-validation-results.json`도 `history/`에 함께 보관하며 원래 날짜·옵션·사용량을 유지합니다.

## JSON 읽기

실제 요청 기록은 `runs/<날짜>/<검사 ID>-<시도>.json`에 있습니다. 날짜는 Asia/Seoul 기준이고 원래 통신 시각은 UTC로 보존합니다.

| 필드 | 의미 |
| --- | --- |
| `evidence_kind`, `transport`, `input_kind` | 실제 wire capture와 저장 대화 관찰, 실제 Provider와 합성 입력을 구분 |
| `basis_commit`, `instrumentation_source_sha256` | 제품 기준과 수집 도구의 정확한 소스 식별 |
| `exchanges` | 인증·라우팅 정보를 제거한 Responses 요청 body와 허용된 응답/SSE event. 수신 순서·terminal usage·HTTP 상태를 보존 |
| `exchanges[].probe`, `exchanges[].arm` | 후보 비교 기록의 입력 묶음과 `current`/`candidate` 구분. 실제 요청·원장 call ID로 연결 |
| `calls`, `profiles` | 앱 호출 원장, 당시 모델·옵션·출력 제한·가격 snapshot. 실제 키·endpoint·원본 프로필은 제외 |
| `runs`, `conversations` | 실행 구간과 도구 근거, 채택한 답변 및 호출 ID 연결. 같은 사용량이 여러 위치에 있어도 중복 합산하지 않음 |
| `workspace`, `uploads` | 합성 파일의 내용·해시, 선택된 Workspace 제외 정책 및 실제 첨부 전달 형태 |
| `result` | 관측 결과와 한계. `unobserved` 또는 `blocked`를 성공이나 Provider 미지원으로 바꾸어 해석하지 않음 |

`request_body_sha256`는 원래 요청 body의 식별자입니다. 민감 필드를 제거한 공개 body를 다시 직렬화한 해시와 같다고 가정하지 않습니다. 공유 ID는 일관된 별칭으로 치환하며 call·실행 구간·대화 참조 간 연결을 유지합니다.

공개 `reasoning_summary`와 reasoning 토큰 수는 서로 다릅니다. [2026-10-29 저장 대화 관찰](history/public-summary-2026-10-29.json)에서 **동일한 `gpt-6-luna` 배포의 비어 있지 않은 공개 요약 반환**을 확인했습니다. 저장된 요약 1개와 호출 원장이 연결되며 새 요청을 보내 얻은 결과가 아닙니다. P03의 짧은 단일 요청은 공개 요약을 반환하지 않았지만, 이 사실은 앞서 확인한 요약 반환을 부정하지 않습니다. 원래 요청 옵션·SSE 델타 시각·최종 답변과의 스트리밍 순서는 보존되지 않아 저장 관찰에서 재구성하지 않습니다.

XLSX의 `B1=37`은 P09 요청에 정상 포함됐습니다. 당시 질문이 `FACT markers`만 요구했고 답변도 `SHEET_FACT`만 반환했습니다. [P09-X1](runs/2026-10-31/P09-X1-01.json)은 동일한 workbook 바이트로 B1을 명시해 `workbook.xlsx: 37`을 받았습니다. 수식 계산이나 합동 Office 요청을 각 파일 형식의 모든 기능에 대한 관찰로 확대하지 않습니다.

[N01](runs/2026-10-31/N01-01.json), [N03](runs/2026-10-31/N03-01.json), [N04](runs/2026-10-31/N04-01.json)는 현재 문구와 격리된 축약 후보의 실제 입출력을 함께 보관합니다. `variant`에는 적용한 정확한 문구·해시·로컬 토큰 추정과 변경 범위가 있습니다. 원본 transcript·디코딩한 첨부·도구 근거는 보존하며 후보가 제품에 적용됐다는 뜻은 아닙니다. 입력 감소와 output/캐시를 포함한 비용 감소를 동일시하지 않습니다.

[N02](runs/2026-10-31/N02-01.json)는 합성 Workspace/legacy/기억 문맥을 구분해 전달하는 역할 prototype입니다. 실제 호스트의 가용성이나 자동 Memory 동작을 관찰한 자료가 아니고, 추가 출처 안내로 입력도 늘었습니다. N04는 실제 Summary 서비스의 지침 비교이며 자동 Memory trigger·채택은 포함하지 않습니다.

[N05](runs/2026-10-31/N05-01.json)는 초기 입력이 P02와 같았지만 반환된 읽기 범위가 달라 타깃 요청 전에 중단된 소스 1회만 포함합니다. Resume/HISTORY 후보 문구는 실제로 전송되지 않았으므로 인계 품질·절약 효과의 근거로 사용할 수 없습니다.

## 공개 범위와 재사용

사용자 질문, 합성 파일·첨부, 도구 정의와 결과, 최종 답변, Provider가 반환한 **공개 reasoning summary**, 사용량·옵션은 보관합니다. 비공개/암호화 reasoning, 인증 헤더·키·endpoint·호스트명, 원본 DB·재개 비밀 문맥은 제외합니다. native 이미지/PDF payload는 합성 입력의 재현에 필요한 범위에서 유지합니다.

알 수 없는 사용량은 `null`이며 숫자 `0`이 아닙니다. reasoning/cache는 total의 부분집합이므로 다시 더하지 않습니다. `partial` 비용은 알려진 구성요소만 포함하고 미설정 요금은 무료로 간주하지 않습니다. 완료·중단·미실행 요청을 구분하고, 저장 관찰을 원래 HTTP 기록으로 재명명하지 않습니다.

기존 자료는 날짜·사용량·옵션·출처를 유지합니다. 새 기록이 같은 관측 범위를 대체할 때도 이전 unknown을 새 요청의 usage로 채우지 않습니다. 한 번의 실제 관찰은 모든 모델·파일·중단 시점에서의 동작을 보장하지 않습니다.
