            Storage diagnostics
            
      
            Basic checks inspect saved settings, profiles, conversations, and databases while Helios is running.
            
      
            Deep checks also verify attachment contents and links across stores. The managed launcher (python app.py) runs deep checks and attachment recovery during a restart.
            
      
            A check must find missing or damaged attachment copies before recovery can start.
            
    
            
    
            
      
            Storage usage
            
      
            Shows file sizes for local data managed by Helios. Workspace files, external backups, and recovery copies are excluded.
            
      
            Sizes are based on file contents as reported by the filesystem. They may differ from allocated disk space or the space you could free.
            
    
            
    
            
      
            Token estimation
            
      
            Local estimates help check input limits and plan memory summaries.
            
      
            Helios uses the installed vocabulary when available. The fallback aims to avoid undercounting text relative to o200k_base. Actual usage comes from the provider.
            
    
            
    
            
      
            Memory summaries
            
      
            Memory carries forward a compact record of earlier goals, decisions and constraints. Original messages stay intact.
            
      
            Generation and background checks are separate permissions. The work budget and call limit also apply to explicitly requested one-time summaries.
            
    
            
    
            
      
            Attachment resource limits
            
      
            Limits for local reading and extraction; the provider checks model capacity. Byte values are exact, and server ceilings may lower them. These limits do not guarantee memory use or processing time.
            
    
            
    
            
      
            Profiles
            
      
            Profiles store connection details and model settings. The default profile is the initial choice for new chats; each chat keeps its own selection.
            
    
            
    
            
      
            Context & memory
            
      
            Profile input settings can use the saved app settings. Output uses the lower explicit app or profile limit. Deployment information supports memory planning.
            
    
            
    
            
      
            Token pricing
            
      
            Optional rates in USD per 1M tokens. Cost estimates depend on the rates and usage reported for each call. The status reflects the current form.
            
    
            
    
            
      
            Recorded usage
            
      
            Totals and call history share the filters and include regeneration, memory summaries, and unsuccessful calls. Costs use the rates saved with each call.
